# 보험 영업 모닝브리프

생명보험·GA 뉴스를 수집해 GitHub Pages에 발행합니다. GitHub Actions는 매일 오전 8시(한국 시간)에 예약되어 있으며 실제 실행 시각은 지연될 수 있습니다.

## 뉴스와 날씨 업데이트

```bash
python3 -m unittest discover -s tests -v
python3 scripts/update_weather.py
python3 scripts/backfill_news.py --recent-days 2 --skip-enrichment
python3 scripts/update_news.py
python3 scripts/build_trends.py
python3 scripts/build.py
```

날씨는 Open-Meteo의 서울 좌표(37.5665, 126.9780) 현재 기상 모델과 당일 최저·최고 예보를 사용합니다. 브라우저에서도 접속 시와 30분마다 갱신합니다. API 호출 실패 시 오늘 날짜의 저장본만 표시하며, 지난 날짜의 예보는 오늘 날씨로 표시하지 않습니다. 별도 API 키가 필요하지 않습니다.

## 지난 날짜 수집

```bash
python3 scripts/backfill_news.py --start 2026-10-01 --end 2026-11-19
python3 scripts/build_trends.py
python3 scripts/build.py
```

보험저널·한국보험신문·보험신보·서울파이낸스의 공개 목록에서 해당 날짜에 발행된 기사를 확인합니다. 하루 최대 5건, 매체별 최대 2건을 선정하며, 관련 기사를 확인하지 못한 날짜는 0건으로 남깁니다. 현재 발행본은 유지합니다.

일일 선정 전의 보험 관련 기사도 `data/articles/YYYY-MM-DD.json`에 URL 중복을 제거해 저장합니다. 과거 목록은 첫 페이지와 공개 ‘더보기’ 페이지를 읽고 발행일·기사 수를 대조합니다. 본문 전체를 복제하지 않고 제목, 공개 발췌, 발행일, 매체와 원문 주소를 보존합니다.

## 주간·월간 동향

주간은 월요일~일요일, 월간은 1일~말일 기준입니다. 최초 수집일 이전과 오늘 이후의 날짜는 요약 범위에 포함하지 않습니다. 현재 진행 중인 기간은 ‘오늘까지 집계’로 표시합니다.

`build_trends.py`는 보존된 전체 기사에서 보험영업 관련 보도를 주제별로 묶어 리포트를 생성합니다. 핵심 요약, 카테고리별 주요 동향·영업적 의미·대응 과제, 종합 시사점, 담당과 관리 지표를 담습니다. 월간에는 주차별 전개도 추가합니다. 각 판단의 근거는 원문 참조 번호로 연결하며, 보도 건수는 수집 매체 범위 내 집계입니다. 인사·부고·일부 행사성 보도 등은 분석에서 제외합니다.

일일 화면은 기사 요약과 영업 시사점을 분리합니다. `build_daily_analysis.py`가 모든 날짜의 선정 기사에 대해 요약, 의미, 현장 적용을 생성해 `data/daily-analysis.json`에 저장합니다. 기존 기사 원본과 요약 문장은 보존합니다. `build_trends.py` 실행 시 이 작업도 함께 수행하므로 매일의 자동 수집·배포에 포함됩니다.

`editorial.py`는 판매 건수·수수료 구성, 생산성, 분급, 보상 한도, 상품 공백, 계약관리 등 구체적인 쟁점에 따라 해석과 대응을 구분합니다. 기사에 없는 금액·시행일·상품 조건을 새 사실로 생성하지 않으며, 시장 전체의 변화나 인과관계를 기사 수만으로 판단하지 않습니다. 현재 설정에서는 별도 유료 AI API 호출 없이 공개 사실과 쟁점별 편집 규칙으로 생성합니다.

`data/trends.json`은 기간 목록이며, 각 기간의 요약과 검색 가능한 원문 목록은 `data/trends/weekly/`와 `data/trends/monthly/`에 저장합니다. 매일 오전 8시 예약 작업에서 최근 이틀의 공개 목록과 RSS를 추가 수집한 뒤 주간·월간 동향을 다시 생성합니다.

`data/backfill-report.json`에 날짜별 수집처·후보 수·선정 수·오류를 기록합니다. 과거 자료를 다시 수집한 이력은 관리 기록으로 보존하며, 화면에는 날짜와 기사 건수를 표시합니다. 예약 실행은 저장소의 Actions 실행 내역에서 확인할 수 있습니다.
